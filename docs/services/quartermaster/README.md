## Notes

- Replaced the separate llama.cpp and stable-diffusion.cpp servers on 2026-11-14. Open WebUI uses it for chat, embeddings, images, and video.
- Routing groups: `igpu` (`Vulkan0`, Iris Xe, persistent, no swap) keeps `bge-m3` and `qwen2.5-coder-1.5b` loaded; `dgpu` (`Vulkan1`/HIP, RX 7900 XT, `swap: true`) swaps `qwen3.8-flash-next`, `qwen-image-2.1`, and `wan2.2-enhanced-i2v` (`moody-krea2-mix` and `moody-pro-mix` are commented out in `models.yaml` and `config.yaml.j2`). Startup preloads `bge-m3`, `qwen2.5-coder-1.5b`, and `qwen3.8-flash-next`.
- The image is rebuilt on Ubuntu 26.04 with the Mesa Vulkan drivers (upstream ships the Vulkan loader only) and pins `llama-server`, `sd-server`, and `strata` directly from `releases.yaml`.
- `sd-server` and Strata have no `/health`; their readiness check is `/v1/models`.
- The dashboard runs with `-admin-open`, so it has no public route.
- Unload a model with `POST /api/models/unload/<id>`.
- Qwen3.8-Flash-Next (`qwen3.8-flash-next`, ISTA GSQ-RCO IQ3_XXS since 2026-11-24, 64k context, DFlash2 with `direct` PLE I/O, refusal-direction `cvec` projection on layers 4-44; on Strata 0.2.20 IQ3_XXS decodes 42 t/s median against 65-68 for IQ2_XS and was chosen for its quality; the IQ2_XS files are kept in DATA, the Q2_0 files were removed on 2026-11-22) is served by Strata, bundled in the image from its release image (`releases.yaml`, `build.strata`): the engine needs only glibc from the system, so it runs beside the Vulkan backends. Quartermaster starts the image's entrypoint as the model command; the entrypoint is patched to serve on loopback without a key and to keep its state in `/data/strata`. The container gets `/dev/kfd`, unlimited memlock and a 2 GB `/dev/shm` for it.
- Strata on the RX 7900 XT (2026-11-20/21, 32k context, DFlash2, tuned preset, `pool-workers=10`, pinned resident experts, learned expert profile): decode IQ2_XS 44-59 t/s, IQ3_XXS 35-40, Q2_0 47-64. On the evaluation sample (GSM8K 60, HumanEval 40, KMMLU 90) IQ2_XS scored 83.2%, IQ3_XXS 83.7%, Q2_0 81.6% (weaker in Korean history).
- Strata 0.2.20 on IQ3_XXS (2026-11-24, 64k context, DFlash2, `direct` PLE I/O, `--resident-experts`): 42 t/s median decode in the benchmark; live chats decode 44.6-49.5 t/s short and 39.4-46.2 t/s at 17k-36.5k tokens of context, with 90-95% of expert reads served from VRAM and none from disk. A UI that divides by wall time shows less, because it counts prefill (5-12 s on long prompts). Expert misses are split between the CPU pool (15.5-18.1 GB/s) and copies over PCIe (6.6 GB/s); Strata tunes the PCIe share to about 0.30 by itself. `--kv-grow` (`STRATA_KV_GROW=1`) does nothing under `--resident-experts`, so it is not set.
- Code autocomplete: `qwen2.5-coder-1.5b` (Qwen2.5-Coder-1.5B Base, imatrix Q5_K_M, 1.05 GiB, Apache 2.0; Base for its native FIM tokens) runs on the Iris Xe with `--ctx-size 4096 --cache-reuse 256`. It stays loaded, but since 2026-11-27 Continue on console has no `autocomplete` role (`ansible/roles/packages/templates/continue/config.yaml.j2`), so nothing calls it; its chat roles still go through Open WebUI. Measured 2026-11-24 with all three resident models, while Continue still called `/v1/completions` directly: 556-780 ms warm, 2.1 s cold.
- Han ban (2026-11-22): every request to `qwen3.8-flash-next` gets `logit_bias` -3 on the 55,659 tokens that contain a Han character or a UTF-8 lead byte E4-E9, set by quartermaster `filters.setParams` from `ansible/roles/containers/templates/quartermaster/han-token-ids.json` (a client's own `logit_bias` is replaced). On IQ2_XS, Korean answers with Han dropped from 9/30 to 0/30, prompts that ask for Han still get it (-5 starts to break that, -6 and -100 break it), speed unchanged, KMMLU unchanged on the items run. The list belongs to this tokenizer; rebuild it when the model changes.
- Image and video models (2026-11-26): `qwen-image-2.1` (`Qwen-Image-2.1-Uncensored-Omni` Q8_0, BF16 VAE, abliterated `Qwen3-VL-8B-Instruct` Q8_0, F16 `mmproj`, and 8-step Turbo LoRA `chatrlabs-omni-turbo-8step-fp32.safetensors` under `loras/` — default image generation and edit model in Open WebUI) and `wan2.2-enhanced-i2v` (WAN 2.2 Enhanced I2V Lightning Edition, `Wan2_2-I2V-Enhanced-High_FP8.gguf` and `Low_FP8.gguf`, 3+3 steps since 2026-11-27 (2+3 before), Euler/simple, CFG 1, default 672×384, 49 frames, 16 fps, `te=vulkan0,diffusion=vulkan1,vae=vulkan1`). `qwen-image-2.1` runs all modules on the RX 7900 XT (`te=vulkan1,diffusion=vulkan1,vae=vulkan1`) with `--offload-to-cpu` so the 17.6 GB of weights reside in system RAM and stream per stage within the 20 GB VRAM limit, `--flash-attn off,diffusion=on`, Euler, 8 steps, CFG 1.0, 1024×1024, and VAE tiling off; passing the Turbo LoRA tag in `--prompt` populates `sd-server`'s default LoRA map so plain `/v1/images/generations` and `/v1/images/edits` calls inherit it automatically. `moody-krea2-mix` (Moody Krea Mix V7 Q8_0) and `moody-pro-mix` (Moody Pro Mix Collector's Edition, Z-Image Turbo Q8_0) are commented out in `models.yaml` and `config.yaml.j2` and kept in DATA. Files that need a Civitai key or manual conversion are marked `manual: true` with their `file` name in `models.yaml`: place them in DATA by hand and check the SHA256 in the comment; the task stops if one is missing.
- Local quantization keeps the original in DATA and writes the GGUF next to it, with Quartermaster stopped (the conversion needs the RAM the chat model holds): `podman run --rm --entrypoint /opt/quartermaster/backends/bin/sd-server/<sd tag>-vulkan/sd-cli -v <DATA model dir>:/w <quartermaster image> -M convert -m /w/<original> -o /w/<name>-Q8_0.gguf --type q8_0`. Krea V7 bf16 26.3 GB became 13.6 GB (5 min), Moody Pro bf16 12.0 GB became 6.5 GB (2 min).
- Video: the image runs `ansible/roles/containers/templates/quartermaster/video/adapter.py` beside the server (`qm-entrypoint.sh`, port 8013 on the host). It offers the OpenAI video API Open WebUI uses (`POST /v1/videos`, `GET /v1/videos/{id}`, `GET /v1/videos/{id}/content`) on top of sd-server's `/sdcpp/v1/vid_gen` jobs, sent through Quartermaster's `/upstream/<model>/` without a `model` field (since sd-server 79dc7ca that field is a model-catalog selection object), defaults to 3 s (49 frames, 16 fps) at 672×384 worth of pixels (in the start image's shape when one is given), caps a larger requested size to that pixel count with the aspect ratio kept (`QM_VIDEO_MAX_PIXELS`), and returns animated WebP, which loops like a GIF (`QM_VIDEO_OUTPUT_FORMAT`; WebM, AVI, or GIF converted with Pillow since sd-server has no GIF output, are the alternatives). Open WebUI has no environment variable for video connections, so `ansible/roles/containers/templates/openwebui/video-connection.py` registers it after each Open WebUI start with the console API key; `VIDEO_GENERATION_TIMEOUT` is three hours.
- Measured through Quartermaster (1024×1024 images, first request includes swapping the chat model out): `qwen-image-2.1` (8-step Turbo LoRA, `te=vulkan1 --offload-to-cpu`) 26.2 s cold T2I, 21.4 s warm T2I, 30.8 s native `/v1/images/edits` I2I (down from 63.5 s with `te=vulkan0`); Moody Pro Mix Q8_0 78 s first, 16 s warm, 9.0 GB VRAM peak (bf16: same picture at a fixed seed, 14.5 GB); Moody Krea Mix V7 Q8_0 48 s first, 26 s warm, 18.1 GB. Image to video (3 s, 49 frames, 16 fps) through the adapter: 624×624 4+4 steps 353 s, 624×624 2+2 205 s (18.8 GB VRAM peak on earlier 242 s run), 512×512 2+3 140 s.
