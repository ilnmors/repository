## Notes

- Replaced the separate llama.cpp and stable-diffusion.cpp servers on 2026-11-14. Open WebUI uses it for chat, embeddings, images, and video.
- Routing groups: `igpu` (`Vulkan0`, Iris Xe, persistent, no swap) keeps `bge-m3` loaded; `dgpu` (`Vulkan1`/HIP, RX 7900 XT, `swap: true`) swaps `qwen3.8-flash-next`, `moody-krea2-mix`, and `wan2.2-enhanced-i2v` (`moody-pro-mix` is currently commented out in `models.yaml` and `config.yaml.j2`). Startup preloads `bge-m3` and `qwen3.8-flash-next`.
- The image is rebuilt on Ubuntu 26.04 with the Mesa Vulkan drivers (upstream ships the Vulkan loader only) and pins `llama-server`, `sd-server`, and `strata` directly from `releases.yaml`.
- `sd-server` and Strata have no `/health`; their readiness check is `/v1/models`.
- The dashboard runs with `-admin-open`, so it has no public route.
- Unload a model with `POST /api/models/unload/<id>`.
- Qwen3.8-Flash-Next (`qwen3.8-flash-next`, ISTA GSQ-RCO IQ2_XS, 64k context, refusal-direction `cvec` projection on layers 4-44; a few Chinese words in Korean answers are accepted, IQ3_XXS was only slightly better and a third slower; the IQ3_XXS files are kept in DATA, its Strata pack and the Q2_0 files were removed on 2026-11-22) is served by Strata, bundled in the image from its release image (`releases.yaml`, `build.strata`): the engine needs only glibc from the system, so it runs beside the Vulkan backends. Quartermaster starts the image's entrypoint as the model command; the entrypoint is patched to serve on loopback without a key and to keep its state in `/data/strata`. The container gets `/dev/kfd`, unlimited memlock and a 2 GB `/dev/shm` for it.
- Strata on the RX 7900 XT (2026-11-20/21, 32k context, DFlash2, tuned preset, `pool-workers=10`, pinned resident experts, learned expert profile): decode IQ2_XS 44-59 t/s, IQ3_XXS 35-40, Q2_0 47-64. On the evaluation sample (GSM8K 60, HumanEval 40, KMMLU 90) IQ2_XS scored 83.2%, IQ3_XXS 83.7%, Q2_0 81.6% (weaker in Korean history).
- Han ban (2026-11-22): every request to `qwen3.8-flash-next` gets `logit_bias` -3 on the 55,659 tokens that contain a Han character or a UTF-8 lead byte E4-E9, set by quartermaster `filters.setParams` from `ansible/roles/containers/templates/quartermaster/han-token-ids.json` (a client's own `logit_bias` is replaced). On IQ2_XS, Korean answers with Han dropped from 9/30 to 0/30, prompts that ask for Han still get it (-5 starts to break that, -6 and -100 break it), speed unchanged, KMMLU unchanged on the items run. The list belongs to this tokenizer; rebuild it when the model changes.
- Image and video models (2026-11-22/23; Qwen Image 2.1 and MiniMax H3-Image removed from the config and from DATA): `moody-krea2-mix` (Moody Krea Mix V7 Q8_0, 1024×1024, 12 steps, Euler A/beta, guidance 2.5 — default image model in Open WebUI) and `wan2.2-enhanced-i2v` (WAN 2.2 Enhanced I2V Lightning Edition, `Wan2_2-I2V-Enhanced-High_FP8.gguf` and `Low_FP8.gguf`, 2+3 steps, Euler/simple, CFG 1, default 672×384, 49 frames, 16 fps). `moody-pro-mix` (Moody Pro Mix Collector's Edition, Z-Image Turbo Q8_0) is defined in comments but currently disabled. Text encoders run on the Iris Xe (`vulkan0`), while diffusion and VAE run on the RX 7900 XT (`vulkan1`). Files that need a Civitai key or manual conversion are marked `manual: true` with their `file` name in `models.yaml`: place them in DATA by hand and check the SHA256 in the comment; the task stops if one is missing.
- Local quantization keeps the original in DATA and writes the GGUF next to it, with Quartermaster stopped (the conversion needs the RAM the chat model holds): `podman run --rm --entrypoint /opt/quartermaster/backends/bin/sd-server/<sd tag>-vulkan/sd-cli -v <DATA model dir>:/w <quartermaster image> -M convert -m /w/<original> -o /w/<name>-Q8_0.gguf --type q8_0`. Krea V7 bf16 26.3 GB became 13.6 GB (5 min), Moody Pro bf16 12.0 GB became 6.5 GB (2 min).
- Video: the image runs `ansible/roles/containers/templates/quartermaster/video/adapter.py` beside the server (`qm-entrypoint.sh`, port 8013 on the host). It offers the OpenAI video API Open WebUI uses (`POST /v1/videos`, `GET /v1/videos/{id}`, `GET /v1/videos/{id}/content`) on top of Quartermaster's `/sdcpp/v1/vid_gen` jobs, defaults to 3 s (49 frames, 16 fps) at 672×384 worth of pixels (in the start image's shape when one is given), and returns animated WebP, which loops like a GIF (`QM_VIDEO_OUTPUT_FORMAT`; WebM, AVI, or GIF converted with Pillow since sd-server has no GIF output, are the alternatives). Open WebUI has no environment variable for video connections, so `ansible/roles/containers/templates/openwebui/video-connection.py` registers it after each Open WebUI start with the console API key; `VIDEO_GENERATION_TIMEOUT` is three hours.
- Measured through Quartermaster (1024×1024 images, first request includes swapping the chat model out): Moody Pro Mix Q8_0 78 s first, 16 s warm, 9.0 GB VRAM peak (bf16: same picture at a fixed seed, 14.5 GB); Moody Krea Mix V7 Q8_0 48 s first, 26 s warm, 18.1 GB. Image to video (3 s, 49 frames, 16 fps) through the adapter: 624×624 4+4 steps 353 s, 624×624 2+2 205 s (18.8 GB VRAM peak on earlier 242 s run), 512×512 2+3 140 s.
